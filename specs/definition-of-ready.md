# Definition of Ready

A feature/spec is ready for implementation only when:

- [ ] purpose is explicit;
- [ ] actor is explicit;
- [ ] scope and non-goals are explicit;
- [ ] preconditions are explicit;
- [ ] inputs/outputs are explicit;
- [ ] business rules are explicit;
- [ ] state transitions are explicit;
- [ ] authorization is explicit;
- [ ] errors are explicit;
- [ ] persistence impact is explicit;
- [ ] idempotency/concurrency behavior is explicit when relevant;
- [ ] acceptance scenarios exist;
- [ ] dependencies are identified;
- [ ] no material assumption remains unresolved;
- [ ] API/UI contract is updated when externally observable;
- [ ] applicable ADRs are current.
